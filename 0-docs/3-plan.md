# 动态反馈闭环实现方案

> 目标：让 App 从「打印出来的计划表」变成「活的教练」

---

## 一、核心问题

现在的 App 像一张印刷品：
```
填资料 → AI生成计划 → 打勾 → 打勾 → 打勾 → （没了）
                                         ↑ 计划永远不会变
```

用户练了没练、练得轻松还是吃力、进步了还是退步了，App 完全不知道。

## 二、解决方案：三层反馈环

```
用户训练 → 点一下感受 → App 记住 → 对比展示 → AI 调整
                                      ↕
                              每次都是活的，不是一次性的
```

---

## 三、第一层：即时感受反馈（前端）

### 交互方式

每个动作右边放三个心情按钮，**不弹窗、不打断、不强制**：

```
□ 开合跳 30秒         自重      😰 👍 💪
□ 徒手深蹲 3×12       自重      😰 👍 💪
□ 弓步蹲 3×12         自重      😰[👍]💪  ← 点了太重了
□ 臀桥 3×15           自重      😰 👍 💪  ← 默认刚刚好
□ 平板支撑 30秒       自重      😰 👍[💪] ← 还能加
```

### 按钮含义

| 状态 | 含义 | 下次效果 |
|------|------|---------|
| **没点（默认）** | 刚刚好，正常完成 | 保持现有量 |
| **😰 太重了** | 太吃力，做不动 | 下次减量 10-20% |
| **👍 刚刚好** | 合适，完成顺利 | 保持 |
| **💪 还能加** | 太轻松，有余力 | 下次加量 10-20% |

### 变更：ExerciseRow.vue

当前只有「😰 太重了」按钮，改为三个表情按钮，默认都不选中。

## 四、第二层：训练记录持久化（后端）

### 新增 workout_history 表

```sql
CREATE TABLE workout_history (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  user_id INTEGER NOT NULL,
  plan_id INTEGER NOT NULL,
  date TEXT NOT NULL,              -- YYYY-MM-DD
  exercise_name TEXT NOT NULL,     -- 动作名称
  target_muscle TEXT,
  planned_sets INTEGER,
  planned_reps INTEGER,
  actual_sets INTEGER,            -- 实际完成组数
  actual_reps INTEGER,            -- 实际完成次数
  feedback TEXT DEFAULT 'ok',      -- 'ok' / 'heavy' / 'light'
  completed BOOLEAN DEFAULT 0,
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);
```

### 新增 API

| 方法 | 路径 | 用途 |
|------|------|------|
| `POST` | `/api/fitness/workout/sync` | 训练完成时批量提交当天记录 |
| `GET` | `/api/fitness/workout/history` | 查某个动作的历史记录 |
| `GET` | `/api/fitness/workout/report` | 查用户本周汇总（给 AI 用） |

### 同步时机

- 每次打勾/反馈时 **就地保存到 localStorage**
- 当天训练全部完成（进度 100%）时 **自动批量提交到后端**
- 或者用户关页面时自动提交一次

## 五、第三层：前端对比展示

每次打开某个动作时，从历史记录中取出上次数据，做对比：

```
□ 徒手深蹲 3×12  自重    😰 👍 💪
   ↑ 上次 12 个 → 这次 15 个  进步了！🔥

□ 弓步蹲 2×12  自重    😰[👍]💪
   ↑ 上次太重了，这次减了一组

□ 臀桥 3×15  自重    😰 👍[💪]
   ↑ 连续 3 次都想加 → 明天加到 18 个
```

### 需要的数据

| 数据 | 来源 |
|------|------|
| 上次同动作的组/次/重量 | localStorage / API |
| 上次的反馈（😰 👍 💪） | localStorage / API |
| 相隔天数 | 本地计算 |
| 趋势（进步/退步/持平） | 对比计算 |

## 六、第四层：定期 AI 调整（后端）

### 新增 AdjustmentAgent

每次生成/重新生成计划时调用，不单独占用时间。

**输入：**
```
用户目标：减脂
原始计划：[动作列表]
训练记录：[过去N天的所有训练数据]
```

**Prompt 调整逻辑：**
```
1. 标记「又能加」2次以上的动作 → 次数+2 或重量+2.5kg
2. 标记「太重了」的动作 → 次数-2 或重量-2.5kg
3. 连续缺勤的动作 → 考虑替换为更简单的版本
4. 单次调整幅度不超过20%（防止大起大落）
```

### 注意

- 不单独新建 Agent，在 TrainerAgent 的 prompt 里加一段训练历史分析即可
- 不是每次打开 App 都调 AI，只在重新生成计划时调用

## 七、优先级

| 优先级 | 内容 | 工作量 |
|--------|------|--------|
| P0 | ExerciseRow 加三个心情按钮 😰 👍 💪 | 小（改1个组件） |
| P0 | 反馈数据存 localStorage，关页不丢 | 小（workout.ts 加逻辑） |
| P0 | 显示「上次vs这次」对比文字 | 中（ExerciseRow 展示） |
| P1 | workout_history 表 + API | 中（后端） |
| P1 | 训练完成自动提交 | 中（前端+后端联调） |
| P2 | AI 根据历史调整计划 | 中（改 prompt） |
| P2 | 每周/每日进度报告 | 大（前端展示） |
