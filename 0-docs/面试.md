  ▎ 4️⃣  "你的 Agent 和普通的函数有什么区别？"

  你至少需要做到什么程度才能面过？

  根据搜索到的要求和面经，你的项目离面试够用还差 3 个关键改造：

  ┌────────────────────────────────────────────────┐
  │ 现在：函数调用链                                │
  │ exercise_agent.search() → plan_agent.assemble() │
  │                                                │
  │ 需要：真正的 Agent 架构                         │
  │ Orchestrator(事件总线)                          │
  │   ├→ Coach Agent (消息驱动)                     │
  │   ├→ Programmer Agent (消息驱动)                │
  │   └→ Analyst Agent (消息驱动)                   │
  │   └→ 每个 Agent 独立状态机 + 工具注册中心        │
  └────────────────────────────────────────────────┘

  具体来说，3 件事做完就能面：

  1. 引入 Agent 通信层 — 不是函数调函数，而是通过一个 MessageBus 发消息
  2. 引入简单的 Agent 状态管理 — 每个 Agent 有 state 属性，Orchestrator 能追踪
  3. 工具注册中心 — Agent 不是硬编码调函数，而是通过 ToolRegistry 注册和调用

  这 3 件事加的程序量其实不大，因为你的业务逻辑已经有了，就是要把调用方式从"直接调函数"改成"发消息给 Agent"。
