# 健身计划引擎设计文档

> 版本：v1
> 日期：2026-06-30
> 状态：设计初稿

---

## 1. 核心理念

### 1.1 从"一次性生成"到"动态演进"

```
❌ 旧模式（当前 demo）：
   LLM → 一次性生成 4 周完整 JSON → 存进 plan_content 一个字段 → 永不更新

✅ 新模式：
   LLM 定方向 + 动作库填充第 1 周
       ↓
   规则引擎驱动（渐进超负荷 + 动作轮换）
       ↓
   每周根据打卡数据自适应调整
       ↓
   每 4 周切换中周期阶段
```

### 1.2 关键转变

| 旧思维 | 新思维 |
|--------|--------|
| 生成整个计划 | 只生成下一周 |
| LLM 决定一切 | LLM 定骨架，引擎算细节 |
| 没有反馈回路 | 每周根据打卡自适应 |
| 静态数据 | 动态演进 |
| JSON blob | 规范化表 + 规则引擎 |

## 2. 周期化体系

### 2.1 三层周期结构

```
大周期（Macrocycle）—— 3~6 个月
  用户设定的总目标（减脂/增肌/塑形/保持健康）
  
  ┌──────────────┐  ┌──────────────┐  ┌──────────────┐
  │  中周期 1     │  │  中周期 2     │  │  中周期 3     │  ...
  │  基础适应期   │  │  肌肥大期     │  │  力量期       │
  │  4 周         │  │  4 周         │  │  4 周         │
  │  3 天/周      │  │  3-4 天/周    │  │  3-4 天/周    │
  └──────┬───────┘  └──────┬───────┘  └──────┬───────┘
         │                 │                  │
    ┌────┴────┐       ┌────┴────┐        ┌────┴────┐
    │ 小周期1  │       │ 小周期1  │        │ 小周期1  │  ← 每周
    │（第1周）  │       │（第5周）  │        │（第9周）  │
    │ 小周期2  │       │ 小周期2  │        │ 小周期2  │
    │（第2周）  │       │（第6周）  │        │（第10周） │
    │ 小周期3  │       │ 小周期3  │        │ 小周期3  │
    │（第3周）  │       │（第7周）  │        │（第11周） │
    │ 小周期4  │       │ 小周期4  │        │ 小周期4  │
    │（第4周）  │       │（第8周）  │        │（第12周） │
    └──────────┘       └──────────┘        └──────────┘
```

### 2.2 中周期阶段定义

| 阶段 | 时长 | 强度（RPE） | 次数范围 | 组数 | 休息 | 目标 |
|------|------|-------------|---------|------|------|------|
| **基础适应期** | 4 周 | 5-6/10 | 12-15 次 | 2-3 组 | 60-90s | 学习动作模式，神经适应 |
| **肌肥大期** | 4 周 | 7-8/10 | 8-12 次 | 3-4 组 | 60-90s | 增肌，容量积累 |
| **力量期** | 4 周 | 8-9/10 | 5-8 次 | 4-5 组 | 2-3min | 力量增长 |
| **减载周** | 1 周 | 3-4/10 | 同上 | 减半 | 同上 | 恢复 |

> **新手路径：** 基础适应期（4 周）→ 肌肥大期（4 周）→ 力量期（4 周）→ 减载（1 周）→ 重复或进阶
>
> **中级路径：** 肌肥大期（4 周）→ 力量期（4 周）→ 减载（1 周）→ 重复

### 2.3 分化方案（每周训练天数对应）

| 天数/周 | 分化方案 | 说明 |
|---------|---------|------|
| 3 天 | PPL（推/拉/腿） | 每个训练日覆盖一个动作模式 |
| 4 天 | 上下肢 × 2 | 上肢日 + 下肢日 各练两次 |
| 5 天 | PPL + 弱项补充 | 推/拉/腿 + 2 天补充日 |
| 6 天 | PPL × 2 | 推/拉/腿 各练两次（重量日 + 容量日） |

## 3. 渐进超负荷引擎

### 3.1 核心规则：双渐进（Double Progression）

每个动作设定一个**次数范围**，策略如下：

```
例子：深蹲，次数范围 8-12 次，3 组

第 1 周：8 次 / 8 次 / 8 次   ← 最低次数开始
第 2 周：9 次 / 9 次 / 9 次   ← 加次数
第 3 周：10 次 / 10 次 / 10 次 ← 继续加
第 4 周：12 次 / 12 次 / 12 次 ← 达到上限

→ 第 5 周（新中周期）：重量 +2.5kg，次数回到 8 次，重新循环
```

### 3.2 渐进参数表

| 用户水平 | 每周加多少 | 方式 |
|---------|-----------|------|
| 新手（前 4 周） | 每次 +1-2 次（次数渐进） | 保持重量，先增次数 |
| 新手（4 周后） | 达到次数上限后 +2.5kg | 双渐进 |
| 中级 | +2.5-5kg 或换更难变式 | 双渐进 + 动作升级 |
| 高级 | 波动周期化 | 每日调整强度 |

### 3.3 减载逻辑

#### 触发方式：自动为主，手动为辅

- **自动插入（默认）：** 每 4 周中周期结束后，自动安排 1 周减载
- **允许跳过：** 用户如果状态好，可以手动"跳过本次减载"
- **允许提前：** 如果用户连续反馈 RPE 偏高（8-9+），引擎可提前触发减载

```
减载规则：
  - 重量降到正常的 50-60%
  - 组数减半
  - 次数不变或略减
  - 目标：恢复 CNS 和关节，预防过度训练
```

**为什么自动比手动更合理？** 新手往往不知道什么时候该休息。自动减载是"强制保险"，让用户主动选择跳过比让用户主动选择减载更符合健康管理的逻辑。

## 4. 动作轮换引擎

### 4.1 轮换策略

同一肌群的主项动作，每 **4 周（一个中周期）** 轮换一次。

```
每个肌群维护一个动作池：

【股四头肌动作池】
  ├── 深蹲（基础期）       ← 第 1-4 周
  ├── 保加利亚分腿蹲      ← 第 5-8 周
  ├── 前蹲                ← 第 9-12 周
  └── 高脚杯深蹲          ← 备用/降阶

【胸部动作池】
  ├── 俯卧撑（基础期）     ← 第 1-4 周
  ├── 哑铃卧推            ← 第 5-8 周
  ├── 上斜俯卧撑          ← 第 9-12 周
  └── 宽距俯卧撑          ← 备用/降阶
```

### 4.2 动作池来源 — 懒加载缓存策略

动作池不预置完整数据，而是采用**用到才拉取（Lazy Cache）** 模式：

```
生成计划需要某个动作时
       ↓
查本地 exercise 表有没有该动作（按 wger_id 或名称匹配）
  ├── 有 → 直接用本地数据
  └── 无 → 从 wger MCP 拉取
              ↓
           自动写入本地 exercise 表（缓存）
              ↓
           后续使用直接走本地，不再请求 wger
```

**设计要点：**
- 本地表随着使用自然积累，不需要批量导入
- 即使 wger 服务不可用，已缓存的动作不受影响
- 每个动作标记：目标肌肉、所需器械、难度等级、动作类型（推/拉/蹲/铰链/核心）
- 不提供手动录入动作入口（避免维护成本和不标准的数据）

## 5. 自适应调整引擎

### 5.1 输入数据（来自每日打卡）

每次训练完成后，用户立即记录：

| 字段 | 示例 | 来源 |
|------|------|------|
| 实际完成的组数 | 3 组 | 打卡 |
| 实际完成的次数 | 10 次 | 打卡 |
| 使用的重量 | 10kg | 打卡 |
| 难度评分（RPE） | 7/10 | 用户反馈 |
| 备注 | "膝盖有点不舒服" | 用户反馈 |

### 5.2 调整规则

```
下一周生成时，对每个动作检查：

┌─────────────────────────────────────────────────────┐
│  条件                               →  调整策略      │
├─────────────────────────────────────────────────────┤
│  RPE ≤ 5 且所有组都完成             →  下周加重量    │
│  RPE 6-7 且所有组完成               →  下周加次数    │
│  RPE 8-9 且完成                     →  保持          │
│  RPE 10 或未完成                    →  减量/降阶     │
│  用户反馈疼痛                        →  替换为备选动作│
│  连续 2 周 RPE ≤ 5                   →  提前轮换动作  │
│  连续 2 周未完成打卡                 →  询问是否太难  │
└─────────────────────────────────────────────────────┘
```

### 5.3 用户连续不打卡的处理策略

| 不打卡时间 | 引擎行为 |
|-----------|---------|
| **1 周** | 正常生成下周，强度保持（不加也不减），并提示"上周没记录，先保持相同强度" |
| **2 周** | 生成下周时自动降强度（回到上一个中周期的起始参数），并询问"是不是太难了/太忙了？" |
| **3 周+** | **暂停生成**，不再自动生成下周。改为发消息问"还想继续吗？要不要重新设定目标？" |

**为什么降强度而不是直接停？** 完全停掉后用户再回来时可能直接流失。降强度保留入口，回来还能继续练，比从零重新开始要好。

### 5.4 降阶/升阶路径

每个动作维护"更难"和"更简单"两个变式：

```
【俯卧撑系列】（从易到难）
  跪姿俯卧撑 → 标准俯卧撑 → 宽距俯卧撑 → 钻石俯卧撑 → 负重俯卧撑

【深蹲系列】（从易到难）
  自重深蹲 → 高脚杯深蹲 → 杠铃深蹲 → 前蹲
```

## 6. 数据库设计（规范化表）

### 6.1 ER 概览

```
macrocycle                ← 大周期（用户设定的总目标）
  └── mesocycle           ← 中周期（4 周一个阶段）
       └── week           ← 小周期（每周）
            └── day       ← 训练日
                 └── exercise_slot  ← 动作安排

exercise                  ← 动作库（独立于计划）
  └── exercise_variation  ← 降阶/升阶变式
```

### 6.2 各表结构

#### macrocycle（大周期）

#### user_current_state（用户当前状态 — 动态配置，随时可改）

## 7. 引擎流程

### 7.1 初始化（用户首次使用）

```
用户填写资料（目标/经验/地点/天数）
       ↓
LLM 选择：
  - 第一个中周期阶段（新手→基础适应期）
  - 分化方案（3天→PPL）
  - 每块肌群分配 N 个动作
  - 估算第一阶段持续几周（默认 4 周）
       ↓
写入 macrocycle（只存目标）+ 第一个 mesocycle
       ↓
从 wger 动作库搜索匹配的动作（懒加载缓存到本地 exercise 表）
       ↓
LLM 精选动作，安排到各天，默认排好日期（如周一/三/五）
       ↓
计算第 1 周的组数/次数（按当前中周期阶段的参数）
       ↓
写入数据库（week + day + exercise_slot）
```

### 7.2 每周生成流程

```
触发条件：
  - 每周日自动触发
  - 或用户点击"生成下周"
       ↓
读取前一周的全部打卡记录（每日训练后的组/次/重量/RPE/反馈）
       ↓
自适应引擎分析：
  - 每个动作是否需要加重量/加次数/降阶/替换？
  - 整体 RPE 是否合理？
       ↓
渐进引擎计算下周参数：
  - 沿用双渐进规则
  - 如果进入新中周期 → 切换阶段参数 + 轮换动作
       ↓
生成新一周数据（week + day + exercise_slot）
  └─ 默认排好日期（按用户习惯，如 Mon/Wed/Fri）
  └─ 用户在界面可自由拖拽，调整哪天练哪个
       ↓
推送通知 / 展示给用户
```

### 7.3 中周期切换逻辑

```
当前中周期的最后一周结束时：
       ↓
读取该中周期的整体数据：
  - 平均完成率
  - 平均 RPE
  - 是否有反复失败的动作
       ↓
决策：
  - 新手完成基础适应期 → 自动进入肌肥大期
  - 肌肥大期完成 → 进入力量期
  - 力量期完成 → 安排 1 周减载 → 重复循环
  - 如果完成率 < 60% → 重复当前阶段
  - 如果用户要求 → 手动选择下一阶段
       ↓
动作轮换：
  - 每个肌群的主项动作换到动作池中的下一个
  - 辅助项保持不变或微调
```

## 8. LLM 的使用边界

| 场景 | 用 LLM？ | 说明 |
|------|---------|------|
| 选第一个中周期阶段 | ✅ | 根据用户目标/经验判断 |
| 选分化方案 | ✅ | 根据天数判断 |
| 首次选动作 | ✅ | 从 wger 搜索结果中精选 |
| 渐进超负荷计算 | ❌ | 规则引擎，简单数学 |
| 动作轮换 | ❌ | 轮换池 + 简单轮转 |
| 自适应调整 | ❌ | if-else 规则判断 |
| 打卡数据分析 | ❌ | SQL 聚合 + 规则 |
| 中周期切换决策 | ✅ | 综合判断，LLM 合适 |
| 动作降阶/升阶推荐 | ✅ | 根据用户反馈推荐变式 |
| 用户疑问解答 | ✅ | 聊天式回答 |

## 9. 生成触发与同步

### 9.1 触发方式

- **自动模式（默认）：** 每周日 20:00 自动触发生成下周计划
- **手动模式：** 用户随时点"生成下周"按钮
- **首次生成：** 用户提交资料后立即生成第 1 周

### 9.2 数据流

```
[生成触发]
    │
    ▼
[读取当前状态] ─────→[状态文件]
    │                      ^
    ▼                      │
[引擎计算]                  │
    │  (LLM / 规则)         │
    ▼                      │
[写入下周数据] ────────────┘
    │
    ▼
[通知用户]
```

## 11. 已决定的方案（讨论总结）

| 问题 | 方案 |
|------|------|
| 动作池怎么维护？ | 懒加载缓存：用到时查本地 → 没有则从 wger 拉取 → 自动缓存到本地 |
| 减载周怎么触发？ | 默认自动（每 4 周一次），允许用户手动跳过，允许引擎提前触发 |
| 连续不打卡怎么办？ | 1 周保持 / 2 周降强度 / 3 周+ 暂停生成并询问 |
| 手动录入自定义动作？ | 不做，避免维护成本和不标准数据 |

## 12. 已决定的方案（第二轮讨论）

| 问题 | 方案 |
|------|------|
| 跳过 vs 调时间 | 引擎默认排好日期，用户自由调整。跳过不补，调日期用户自己拖 |
| 变式链怎么构建 | 常见链手动预置（~20组），新动作让 LLM 顺带生成"更容易版"和"更难版" |
| 中周期切换确认 | 默认自动切换，提前在下周计划页展示"下一阶段预告"，用户可选择"再练两周"停留 |
