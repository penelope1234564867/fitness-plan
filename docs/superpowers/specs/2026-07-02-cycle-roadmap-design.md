# 训练周期路线图展示设计

> 2026-07-02 — 基于 brainstorming 和竞品调研结果

## 问题

当前项目虽然在后端实现了完整的大周期（Macrocycle）→ 中周期（Mesocycle）→ 小周期（Week）三层体系，但前端用户完全感知不到这个层级结构。CycleInfo 只显示当前阶段标签和本周进度，用户看不到：
- 自己在整个大周期中的位置
- 接下来要经历哪些阶段
- 历史阶段的完成情况
- 不同训练目标有不同的阶段路线

## 目标

在不改变核心训练流程的前提下，让用户：
1. **看到全景** — 打开个人主页即可看到整个大周期的路线图
2. **感知位置** — 清晰知道自己当前在哪一阶段、第几周
3. **理解阶段价值** — 每个阶段都有标签和说明，知道训练目标是什么
4. **掌控进度** — 历史阶段有完成率数据，未来阶段有占位符

### 关键架构决策：混合生成策略

**原则：框架预生成，内容周更**

| 层级 | 生成时机 | 内容 |
|------|----------|------|
| 大周期（Macrocycle） | init-plan 时创建 | 目标、状态、起止日期 |
| 中周期（Mesocycle） | init-plan 时全部创建 | 阶段类型（根据目标）、周数、排序 |
| **小周期框架（Week）** | **init-plan 时预创建** | **所有周的 week_number、status=pending、占位日期** |
| **训练日框架（Day）** | **init-plan 时预创建** | **每训练日的 day_order、date、focus、day_label（无 slots）** |
| 具体动作（ExerciseSlot） | 每周 generate-next 时生成 | 具体动作、组次重量、热身/有氧/拉伸 |

这样做的原因：
1. **路线图需要完整数据**才能展示——如果没有预创建 Weeks/Days，路线图只能显示阶段名，无法显示"第几周"
2. **exercises 不能预生成**——它们需要基于上周打卡数据自适应调整
3. **在 init-plan 里一次性创建 4 周（一个 mesocycle）的框架**，对数据库和性能几乎没有压力

### 组件拆分

**新建组件：**

1. **CycleRoadmap.vue** — 水平路线图条
   - Props: macrocycle, mesocycles, currentWeek
   - Emits: 无（纯展示）
   - 子组件：PhaseSegment（单阶段块）

2. **PhaseDetail.vue** — 当前阶段详情卡片
   - Props: mesocyclePhase, completionRate, weekNumber, totalWeeks
   - Emits: 无

3. **CycleHistory.vue** — 历史阶段完成列表
   - Props: mesocycles[]
   - Emits: 无

**改造组件：**

4. **CycleInfo.vue** -> 重做为 **WeekProgress.vue** — 放在日历上方的进度条
   - 删除：路线图内容
   - 保留：周进度、生成下周按钮
   - 增加：下一个阶段预告

### 数据流

```
用户 init-plan
  -> 后端创建 Macrocycle + Mesocycles + Weeks 框架 + Days 框架
  -> 生成 Week 1 的具体动作（ExerciseSlot）
  -> SSE 返回 Week 1 完整数据 + 宏周期结构
  -> 前端 store 存储 macrocycle/mesocycles/currentWeek
  -> ProfilePage 渲染路线图
  -> MainPage 渲染精简进度条

用户完成本周 -> 点击"生成下周"
  -> 后端生成下一周的 ExerciseSlot
  -> 返回新 Week 数据
  -> 前端更新 currentWeek + 路线图状态
```

### API 变更

**init-plan 修改：**
- 响应中增加 `macrocycle_id`、`mesocycle_id`、`macrocycle_detail` 完整结构
- 预创建 4 周的 Week 和 Day 框架

**generate-next 修改：**
- 响应中增加 `macrocycle_detail` 以便前端同步更新路线图

**后端 `_build_macrocycle_detail` 补充：**
- 每个 MesocycleDetail 中 Weeks 额外增加 `completion_rate` 字段
- 通过 Day.is_completed 计算每个周的完成率

**新增前端 API：** 无，复用已有 `GET /api/fitness/macrocycle/{id}`

### 后端改动（目前架构）

**mesocycle_manager.py：** 增加 `generate_mesocycle_skeleton()` 函数，创建一个 mesocycle 内所有 Week 和 Day 的框架行

**generator.py：** `generate_init_week` 中调用 skeleton 函数预创建未来 3 周 Week+Day 框架

**plan_service.py：** 增加编排，在 init 时创建 4 个 mesocycle 的全部 Week+Day 框架

**fitness.py 路由：** init-plan 响应中返回 macrocycle 完整结构

## 竞品调研参考

- **phase.fitness**：水平路线图条 + 颜色编码阶段 + 容量柱状图
- **Budy**：基于块（block）生成，3-6 周一块，AI 在块结束时重新评估
- **omnilift**：Mesocycle builder，用户可看到完整的 4 周块
- **Musely**：一次性生成完整 4 周计划，但它是静态计划无需自适应
- **MySetPlan**："full monthly plan generated upfront, adapted monthly"
